# Corrected compact-fold extraction

This directory records the 24 August 2026 Charon/Aeneas extraction of the
production `CompactBTerminalWeights::fold` method.

The previous checked snapshot translated the loop body but assembled the
mutable-array write-back around an empty iterator. That was a proof-artifact
bug, not a Rust bug. The Aeneas patch here retains the exact loop value consumed
by the backward iterator function. The regenerated loop therefore returns the
reconstructed iterator itself, and the outer function passes that iterator to
the array write-back function.

`generated/V5CompactFoldExtendedFull.raw.lean` is the direct Aeneas output.
`generated-normalization.patch` performs only three backend/library
normalizations:

1. use the pinned Lean 4.32 Aeneas imports;
2. render the three shift counts as unsigned values expected by that library;
3. replace the external declaration for mutable-array `into_iter` with the
   existing exact `Array.to_slice`/`Array.from_slice` model.

`generated-import-namespace.patch` then changes only the outer namespace to
`V5RelationCompactFoldGeneratedExact`. This makes the corrected extraction
importable beside the older loop-induction artifact without two files claiming
the same Lean module name. Public source-closure proofs import the explicitly
named corrected module; the older module remains available only to the already
checked compatibility/induction layer.

The normalized, namespaced generated file contains no `axiom` or `sorry` and
compiles with Lean 4.32. The manifest records every source, tool, patch,
generated file, and compiled-object hash. The 1.7 MB LLBC is archived on the
project NUC rather than duplicated in Git.

The extraction-only Rust wrapper merely makes the private inherent method a
Charon root. The host-only Solana patch removes `cdylib` while retaining
`rlib`; neither patch changes the deployed verifier source or its semantics.

## Accepted-caller integration correction

The older accepted-caller snapshot imports
`generated/V5RelationCompactFoldGenerated.lean`. Its loop body came from the
earlier extraction, but its small outer mutable-array assembly was handwritten
because that Aeneas version did not translate the wrapper. It is not claimed
to be untouched raw Aeneas output.

The historical assembly applied the loop's write-back function to an empty
iterator. That loses the ten updated blocks in the Lean proof artifact. The
deployed Rust applies the write-back to the iterator created from the input
block array. `accepted-caller-writeback.patch` records the one integration
change that makes the accepted-caller model do the same thing. It changes no
Rust source or deployed program.

The correction is checked independently against the new extraction rather
than treated as generated by assertion. The direct 24 August Aeneas output is
preserved as `generated/V5CompactFoldExtendedFull.raw.lean`; the normalized
`V5RelationCompactFoldGeneratedExact` module retains the corrected iterator
returned by Aeneas. The exact-to-legacy bridge proves that this extracted
program and the corrected accepted-caller program agree for all four fold
counters used by the release.
