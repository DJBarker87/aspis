## Result

K1.6 is **conditionally closed on the four explicit K1.2--K1.5 stage
interfaces**.  The Tag-73-specific Fiat--Shamir/compiler step itself is now
proved.  There is no BCS theorem parameter, trace-cover premise, abstract
restore function, aggregate upstream inequality, `sorry`, or project axiom in
the principal theorem chain.

Literal instantiation of BCS 2016, Theorem 7.1 remains a no-go: Tag-73 is not
the Section-6 compiler.  BCS guided the construction, but the deployed
coupling is proved directly over the actual scheduler, duplex, lazy oracle,
and finite master tape.  In particular, the published
`3(Q^2+1)/2^256` term is not used.

The concrete compiler chain is:

```text
fixed-instance deployed source acceptance
  ⊆ fixed clean same-tape event ∪ exact causal target event

fixed clean same-tape event
  ⊆ inhabited exact scheduler/state-map/resource input
  ⊆ valid fixed-instance client extraction ∪ four K1.2--K1.5 errors

Pr[exact causal target event]
  ≤ (F + choose(F,2) + F*G) / 2^256.
```

Here

```text
M = Q + 1511 + R*(Q + 1511)
F = M + 2R
G = Q + 1511 + R*(2Q + 1511),
```

where `Q` includes every first-run adversary SHA call, including all Merkle,
sampler, and three grinding regions, and `R` is the number of requested atomic
output/advance forks.  `F` counts all uniform full-256 coordinates, including
the two programmed coordinates per fork; `G` counts all actor oracle calls.

The exact finite-count compiler term is

```text
(F + choose(F,2) + F*G) * (2^256)^(F-1) / (2^256)^F,
```

and its positive-exposure form is

```text
(F + choose(F,2) + F*G) / 2^256.
```

The principal raw theorem is

```text
Pr[fixed-instance Tag-73 source acceptance]
  ≤ Pr[valid fixed-instance witness returned by the actual client]
    + εK1.2 + εK1.3 + εK1.4 + εK1.5
    + (F + choose(F,2) + F*G)/2^256.
```

The normalized form subtracts this raw error with loss one.  No soundness
error or extraction error is divided by grinding work.  The loss-one form
comes from the proof-relevant four-stage classifiers: on an inhabited
operational input they either return the actual fixed-instance extraction
certificate or one of the four named errors.

The compiler-side closure is operational, not merely arithmetic:

- every actual `.forkAdvance` coordinate has a proof-relevant certificate for
  the exact executable preparation that emitted it;
- the query-DAG checkpoint is a deterministic function of the generated
  replay prefix, and `phaseForCursor` makes the verifier phase functional at
  that checkpoint; the scheduler-side certificate then identifies the
  literal parent transition selected by the executable preparer;
- the selected parent transition is in a closed verifier history;
- the restored state is complete, nonempty, and previously seen;
- failed programming, prover replay, binding, verifier replay, and resource
  branches retain the pair certificate;
- successful children are appended only after their exact future-free path
  proves their final history closed;
- the full scheduler is factored into the two root machine prefixes and the
  literal client tail at the computed continuation fuel (not the false
  same-fuel cursor equation); and
- Q1, verifier/replay queries, forks, programming points, restarts, verifier
  transitions, runtime, timeout absence, and the three separately positioned
  grinding query counts are read from the actual run and bounded explicitly.

The remaining assumptions are genuinely upstream K1.2--K1.5 work: four
dependent certificate/error families, their four classifiers, and four
separate error-measure bounds.  This is exactly the modular boundary allowed
for K1.6; none of those fields states a Fiat--Shamir/compiler conclusion.

These are probabilistic statements.  Nothing claims pointwise witness
extraction from every accepting proof.  Observed/simulated-proof security is a
separate stronger theorem and still requires canonical simulation,

## Exact SHA duplex

Let `S` be the current 32-byte transcript state, initially zero. The deployed
primitive is:

```text
absorb(label, data): S := SHA256(S || 0x00 || label || data)
squeeze block:       out := SHA256(S || 0x01)
                     S   := SHA256(S || 0x02)
grind(nonceLE):      SHA256(S || 0x03 || nonceLE)  -- S is unchanged
```

Every challenge sampler consumes a sequential stream of squeeze blocks; a
rejected field word advances that same stream. Thus a challenge is bound to
the complete preceding transcript state, but challenge calls are not assumed
independent.

The ordinary QM31 sampler uses at most four blocks: four limbs, eight candidate
31-bit words per limb, eight words per block. The nonzero-QM31 and secure-circle
samplers each make at most three outer attempts and therefore consume at most
twelve blocks. Sampler exhaustion is an explicit verifier rejection and
honest-completeness event, not an unbounded ideal sample or an automatic
plain extraction-loss term.

[`V7Tag73SamplerDecoder.lean`](../../AspisFormal/AspisFormal/K1/V7Tag73SamplerDecoder.lean)
implements those byte decoders and the 64-draw q16 scan. The secure-circle
parameter is completed in
[`V7Tag73SecureCircleMap.lean`](../../AspisFormal/AspisFormal/K1/V7Tag73SecureCircleMap.lean)
using the exact deployed tower. The remaining source-level statement that a
Rust `u32 & (2^k-1)` is this arithmetic low part belongs to the named
Charon/Aeneas correspondence boundary; the exact tower already proves the
mathematical low-31 bit-and identity.

## Observed-proof extraction experiment

[`V7FsAokExperiment.lean`](../../AspisFormal/AspisFormal/K1/V7FsAokExperiment.lean)
contains the operational game, not a one-proof decoder:

- one finite master PMF fixes all first-run, simulator, verifier, replay, and
  extractor coins;
- every oracle table entry and ordered query is recorded, with actor
  `adversary`, `simulator`, `verifier`, or `extractorReplay`;
- `Q1` is frozen from adversary calls when the first run halts; later verifier
  and extractor calls do not retroactively enter `Q1`;
- programming is a separate operation and aborts if the input was previously
  defined, even with the same output;
- fresh queries are controlled by a function of the complete ordered history
  and the current input;
- the original experiment shell can record an opaque restart checkpoint, but
  that field is only a game surface and is not used to justify K1.6;
- `V7FsStateRestorationCoupling` instead closes a start-only capability over
  one hidden random tape, computes the original execution from that closure,
  and derives each operational pause by replaying a concrete prefix; the
  extractor cannot read or replace the tape and is not handed an arbitrary
  adversary-memory checkpoint;
- oracle/program/query, fuel, runtime, restart, three grinding-query, q16
  branch, verifier, and simulated-proof budgets are explicit;
- a checked Markov inequality converts an expected natural-number cost into
  the explicit probability of exceeding a nonzero hard cutoff;
- acceptance, resource abort, programming abort, WUR failure, transcript
  coupling failure, and valid witness extraction are separate events; and
- the extractor structure contains only an algorithm. It has no
  `compiledBound`, `extract_sound`, or conclusion-shaped field.

Freshness has two levels. Ganesh et al.'s observed target requires pair
freshness `(instance, proof)`. A globally fresh attempt/proof-account ID is
strictly stronger, and Lean proves `AttemptFresh -> PairFresh`. Production
binds the proof account into the precommit and both root salts, but a finalized
account can be submitted again. Therefore deployed Tag 73 does **not** by
itself establish global attempt freshness relative to an arbitrary simulated
history. The observed-proof route needs FS-WUR unless the surrounding game
adds and proves that stronger freshness condition.

The older `ClassicalFSCompiler` is not an FS proof: its `compiledBound` member
is already the desired inequality. Likewise, the Pool
`KnowledgeExtractorInterface` only types an extractor boundary; a public proof
and one observed SHA query log do not construct the same-randomness black-box
replays required by BCS or Ganesh. Neither interface is used to discharge the
proved custom coupling.

## Exact raw-error status

The Tag-73 compiler error is now justified from the actual finite lazy-oracle
target tree.  The following are deliberately absent:

- the BCS `3(Q_RO^2+1)/2^256` term, because literal applicability fails;
- a `C2-after-lambda-chi` loss, because adaptive C2 is a legal later prover
  message in a multi-round IOP;
- three independent work-error terms, because the leading-zero predicates can
  be erased pointwise while retaining every nonce, query, and absorb;
- bounded-sampler exhaustion or all-q16-fail probabilities, because those are
  verifier rejection/honest-completeness events unless a coupling explicitly
  conditions them away; or
- simulator/WUR terms, because those belong only to the stronger observed-
  proof theorem.

The named audit partition is:

```text
unqueried transcript-driving output prediction
full-256 input/state/output collision
forward reference or programming conflict
adaptive q16 cloned-forest failure
fixed-instance/attempt binding failure
strict query/restart/runtime/timeout failure.
```

The operational proof resolves this partition rather than merely listing it:

- both squeeze inputs are syntactically distinct;
- transcript and typed-Merkle SHA input grammars are disjoint;
- the no-pair same-start and output-oblivious replay theorems make the two
  unqueried-output prediction classes empty for this concrete scheduler;
- output/state collisions and forward-reference/programming conflicts are
  subsets of the one seeded causal target event;
- successful strict checked refinement constructs the exact q16 forest, so
  the q16 forest-failure event is empty;
- fixed clean roots preserve the complete fixed instance and all five binding
  projections, so binding failure is empty; and
- every clean completed input carries the actual resource certificate and a
  proof that its runtime lies below the timeout cutoff.

Thus the compiler contributes the causal target event exactly once.  Its
coefficient is `F + choose(F,2) + F*G`; no independence assumption is used.
The leading `F` seeds the public dummy initial digest and prevents a later
sampled coordinate from silently colliding with it.

The four upstream quantities remain separately typed:

```text
εK1.2,two-tree-208
+ εK1.3,circle-list
+ εK1.4,coherent-chain
+ εK1.5,witness.
```

They are raw event-measure bounds and may sum above one.  The K1.2 208-bit
term is never replaced by a generic 104-bit birthday slogan.
