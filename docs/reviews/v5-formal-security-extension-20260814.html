The main protocol mismatch

S-two Theorem 21 proves an opening protocol that runs FRI on both the original function and an out-of-domain quotient. Tag-67 has no quotient word, commitment, or opening. It runs FRI on the ordinary 19-column batch and checks two claimed values per round through a separate degree-six relation calculation.

This is a different protocol, so Theorem 21 cannot be cited as a direct proof of Tag-67. Lean now gives a deterministic by-cases argument for the exact four folds: accepted ideal FRI produces one matching initial-list member unless a named query, fold-reduction, or list-size failure occurs. It does not prove that S-two bounds those failures for V5.

How serious is this? It is the central remaining gap for a numerical claim about malicious proofs accepted by the deployed verifier. No concrete forgery or mathematical break was found, but absence of a found attack is not a security proof. The repository should not yet claim a proved deployed 100-bit false-acceptance rate or a numerical theft bound.

What still has to be connected

  • Connect raw accepted Merkle openings and the Rust FRI callback to the ideal words and exact query checks used by the Lean model.
  • Prove exact S-two applicability and probability bounds for the four arity-four no-predecessor failures, and apply the actual Guruswami--Sudan list theorem to the V5 encoders.
  • Extract the full 19-lane trace from authenticated C1/C2 data and connect successful Rust relation checking to the maintained pure model.
  • Supply the missing Fiat--Shamir/work, SHA-256, Poseidon2, polynomial-commitment, FRI, extraction, PDA, Rust-correspondence, and Solana-runtime probability statements.
  • Connect the marker state model to the fixed-victim theft game and to Solana's actual locking, rollback, ownership, and finalized persistence.

Earlier work still applies

The previously reviewed Lean modules still provide useful conditional steps: a Merkle collision reduction for two different leaves at one tree position, a three-event false-acceptance union bound, and an eight-case split for the fixed-victim attack game. None of those earlier results supplies the remaining callback, Merkle, fold-reduction, lane-extraction, or primitive-security probabilities.

Safe publication wording

It is accurate to say that Lean now checks the exact ideal bounded query experiment, the fixed-set without-replacement probability, a sequential nullifier-marker model, the exact candidate and verifier-weight relation folds, candidate-relative inclusion in the counted event, the 32 × 240 / |K| single-list repair bound, all four numeric list expressions, and the five-way accepted-false split. The extracted selector proof checks only the three-way byte split. It is accurate to say that the maintained model now sends every accepted false execution to an explicit unbounded failure branch or the bounded repair event. It is not accurate to say that the four other branches have been bounded, or that deployed V5 theft resistance or the deployed 100-bit security claim has been proved end to end.
