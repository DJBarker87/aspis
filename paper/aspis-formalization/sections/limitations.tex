\section{Assumptions and remaining verification}
\label{sec:limitations}

Most of the mathematical core is checked in Lean.  The selected accepting
verifier path is connected to those models through generated Lean and bridge
proofs through the complete maintained relation caller.  One successful
translated callback supplies the decoded relation data, twelve-component main
accumulator, compact accumulator, and both final dot products without a
caller-supplied model-equality premise.
Published decoding and Fiat--Shamir results, primitive
security, translation and proof-tool correctness, compilation, and Solana
runtime behavior remain stated inputs for the concrete instantiation.

\subsection{End-to-end code connection}

For the released proof callback, the accepted-execution work starts from
success of the translated production entry point.  It derives the parsed
values, transcript challenges, work checks, selected queries, authenticated
openings, FRI comparisons, final polynomial, exact claim table, initial
relation value, and decoded relation tail from that same run.  These are not
independent hypotheses.  The same selected four-round execution supplies the
general accumulator's exact twelve terminal weights and the compact
accumulator's full state evolution.  The outer accepted-execution theorem then
derives the maintained security-event conclusion.

The pinned Aeneas version emitted an ill-typed back-translation for the
compact mutable fold iterator.  Audit then found that the first handwritten
replacement reconstructed the array from an empty iterator and discarded its
writes.  Lean records a counterexample to the old wrapper and now uses a
corrected wrapper that rebuilds from the updated original iterator.  The Rust
function and deployed program were unaffected.  An extended, pinned Aeneas
translation of the unchanged function emits the correct iterator handback and
compiles under Lean 4.32.  Its generated caller is connected to the accepted
fold execution used by the outer theorem.

This is not whole-program verification.  The source proof covers the selected
accepting verifier callback, not every dispatch, upload, diagnostic, host, or
cleanup path.  The surrounding spend transition and close/refund models retain
their stated Rust-to-model and Solana-runtime boundaries.  Charon, Aeneas,
Lean, the compiler, and the Solana runtime are trusted rather than verified by
the result.  The exact source path is in \cref{app:source-checklist}.

The translated entry path checks consistency between its live statement and
statement digest.  The present source theorem does not yet identify every
field of that Rust statement with the abstract public-statement object used by
the false-acceptance and theft experiments.  This missing model link is one
reason the report does not claim a complete deployed-theft theorem.

\subsection{How the assumptions enter the theorem}

The general audit ledger retains source and runtime mismatches as named events
so that none can disappear from the proof.  Completed accepted-path theorems
discharge the selected deterministic verifier correspondence through the
complete relation caller.  The
conventional cryptographic statement assigns probability only to
the remaining protocol, primitive, credential, toolchain, and runtime events.
It does not assign a fictional tiny failure probability to parser correctness,
compiler correctness, or rollback semantics.

\subsection{V5 soundness status}

Lean checks the exact circle domains, encoder order, degrees, distances,
local radix-four folds, prefix-conditioned bad sets, compatible candidate
chain, relation reductions, query calculation, adaptive fresh-oracle count,
and final probability arithmetic.  This proves the V5-specific four-way FRI
part rather than assuming that the different S-two folding protocol applies
unchanged.

The final event interface states how the event extracted from the selected
production path is identified with the event covered by the published BCS
state-restoration theorem.  The deterministic transcript schedule, samplers,
both accumulators, and complete relation caller are checked in the selected
source bridge.  No current theorem, however, references both the final
selected-call conclusion and the work-normalized adversarial experiment.  The
missing experiment-level join must construct one causal probability law, lift
the deterministic six-way classification to event inclusion, and prove the
work-normalization and external-event connections.  The published BCS
theorem and SHA-256 random-oracle model remain external cryptographic inputs,
not an unfinished V5 FRI code theorem.

The \(2^{-100}\) theorem is a work-normalized conditional budget theorem.  The
resource-bounded form in \cref{eq:resource-bounded-advantage} and the raw theft
theorem keep the completed-work factor out and report their remaining terms
separately.

\subsection{Standard trusted inputs}

The development uses the following normal assumptions:
\begin{itemize}[leftmargin=*]
  \item correctness of the published circle-code decoding result;
  \item correctness of the published BCS state-restoration and Fiat--Shamir
        soundness result for the modeled public-coin IOP;
  \item collision, target-preimage, and modeled random-oracle security for
        SHA-256 where each property is used;
  \item the stated Poseidon2 implementation and security properties;
  \item correctness of Lean, mathlib, Charon/Aeneas for the translations used,
        Rust, LLVM, and the Solana build tools; and
  \item the stated Solana behavior for address derivation, account ownership,
        writable locks, rollback, committed persistence, and finalized state.
\end{itemize}

These assumptions need to be named and given suitable parameters in a concrete
security claim, but they do not normally need to be reproved inside the Aspis
development.  Known-answer tests and reproducible builds support implementation
identity; they are not used as proofs of collision resistance.

\subsection{Privacy scope}

The mathematical hiding theorem proves witness independence for its complete
finite modeled view.  Extending it to a deployed zero-knowledge claim requires
the production masking, entropy, retry, commitment, serialization, and public
observation model.  This is additional work only if the paper claims full
deployed zero knowledge; it is not needed for the private-spend soundness
theorem.
