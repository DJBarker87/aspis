\section{Introduction}
\label{sec:introduction}

Transparent arguments replace a trusted setup with public randomness and
hash-based commitments.  Their compact verification procedures are attractive
for blockchains, but the security proof usually describes an abstract
verifier while the chain executes a parser, transcript engine, opening
checker, algebraic checker, and state-transition program.  An error at any
boundary can invalidate a correct protocol proof.  In a private-payment
application, the executed statement must also be the statement authorized by
the user, and acceptance must control the one-time marker that prevents the
same note from being spent twice.

This paper studies that full evidence chain for \Aspis{}, a transparent
private-spend verifier implemented as a Solana program.  A spend consumes one
hidden input note and creates one hidden output note.  The public statement
contains the old and new pool commitments, a public one-time tag called a
\emph{nullifier}, and the public value balance.  A successful transaction
checks a transparent proof and records the nullifier and new pool commitment
atomically.

Our principal contribution is an end-to-end formal result for every successful
execution of the deployed proof-checking path.  We extract that path from
the Rust verifier, translate it into Lean~4, and prove that success entails the
complete body of evidence required by the mathematical verifier.  In
particular, the theorem derives the statement binding, transcript challenges,
proof-of-work checks, authenticated openings, low-degree-test queries and
folds, decoded algebraic claims, relation checks, and final accumulators from
one execution.  This \emph{same-execution property} rules out a subtle but
important proof gap: facts established about different successful runs cannot
be combined as though they described one run.

The source theorem feeds into a larger Lean development of the spend relation,
finite-field domains, low-degree testing, bounded distinct-query sampling,
theft reductions, and nullifier-controlled state transition.  A separate
probability experiment accounts for accepted false statements.  It proves a
finite failure decomposition and a conditional work-normalized bound.  The
theorem statement names every assumption needed for that bound.

\subsection{An end-to-end evidence pipeline}

We use \emph{end-to-end} to mean that the formal and empirical evidence can be
followed across the complete successful proof-checking path, with each handoff
made explicit.  The evidence has five layers:

\begin{enumerate}[leftmargin=*]
  \item \textbf{Protocol model.}  Lean definitions state the private-spend
        relation, transcript schedule, authenticated-opening rules,
        low-degree test, algebraic relation, security experiment, and state
        transition.
  \item \textbf{Implementation connection.}  A reproducible translation
        selects the deployed Rust path and represents its control flow and
        data transformations in Lean.  Correspondence proofs show that a successful
        call produces the values consumed by the protocol model.
  \item \textbf{Same-execution composition.}  One final theorem composes all
        correspondence proofs from a single call.  It assumes neither a precomputed
        accumulator equality nor agreement with a separately executed model.
  \item \textbf{Deterministic build identity.}  A manifest records the source,
        toolchain, dependencies, program binary, and hashes needed to reproduce
        the deployed artifact.
  \item \textbf{Execution evidence.}  An archived finalized transaction binds
        the program, proof bytes, public statement, compute usage, nullifier,
        and before-and-after pool state.
\end{enumerate}

paper uses mathematical names for the results; an external artifact guide maps

This separation keeps the argument readable while preserving exact audit

The final source theorem is stronger than a collection of local correspondence
lemmas.  Given any successful call, it reconstructs the exact public input
digest and transcript; verifies six sequential work conditions; obtains
eighteen distinct query positions; authenticates five opening sections;
checks four rounds of the low-degree test and its final polynomial; decodes
seventy-six algebraic claims and the complete relation message; and derives
both terminal accumulator equalities.  The downstream security conclusion is
independent of the return value of the final helper because the required
opening, folding, and relation evidence has already been derived.

\subsection{Security statement}

The security model places the verifier and adversary in one finite probability
space.  Lean proves that every accepted false statement belongs either to the
ideal low-degree-and-relation failure event or to an explicitly represented
cryptographic, credential, compilation, or runtime event.  The proof uses a
union bound and requires no independence assumption between those events.

For the evaluated parameters, the work-normalized contribution of the modeled
protocol events is at most
\[
  0.7\cdot 2^{-100}.
\]
If the combined probability assigned to the remaining external events is at
most \(0.3\cdot2^{-100}\), the total accepted-false probability is at most
\(2^{-100}\).  Work normalization charges an adversary for the repeated
trials needed to satisfy the proof-of-work conditions.  We therefore also
report a raw per-attempt view; its dominant explicit term is approximately
\(2^{-70}\), before adding the named external terms.  Keeping these two
accountings separate prevents a work factor from being silently interpreted
as a raw cryptographic advantage.

Two composition assumptions determine the precise reach of this result.  The
first identifies, field by field, the live statement checked by the translated
Rust path with the abstract statement used in the security and theft
experiments.  The second embeds the deterministic classification of a
successful call into the causal probability experiment used for the numerical
bound.  The paper states these assumptions at their points of use, and the
artifact package exposes the interfaces needed to discharge them.

\subsection{Contributions}

The contributions are:
\begin{itemize}[leftmargin=*]
  \item An end-to-end Lean theorem that derives all acceptance-critical
        transcript, authentication, low-degree, and algebraic evidence from
        any successful translated execution of the deployed Rust verifier.
  \item A machine-checked model of the evaluated private-spend verifier,
        including its exact finite-field domains, four-round low-degree test,
        bounded distinct-query sampler, one-input/one-output spend relation,
        theft reductions, and nullifier-controlled state transition.
  \item A single security experiment and checked failure decomposition leading
        to a conditional \(2^{-100}\) work-normalized bound, accompanied by a
        separate raw accounting and an explicit interface for every external
        assumption.
  \item A reproducible evidence package that connects the formal development
        to translation inputs, deterministic program bytes, proof bytes, and
        a finalized Solana execution with before-and-after state.
\end{itemize}
