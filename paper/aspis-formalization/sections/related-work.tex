\section{Related work}
\label{sec:related-work}

\subsection{Transparent arguments}

Aspis builds on interactive oracle proofs and the FRI family of
Reed--Solomon proximity tests
\cite{BenSassonChiesaSpooner2016,
BenSassonBentovHoreshRiabzev2018FRI,
BenSassonBentovHoreshRiabzev2018STARK}.  DEEP-FRI improves proximity testing
with out-of-domain samples, while WHIR combines proximity testing with
multilinear evaluation claims
\cite{BenSassonGoldbergKoppartySaraf2020,
ArnonChiesaFenziYogev2025WHIR}.  Circle codes and Circle STARKs provide smooth
evaluation domains over Mersenne fields
\cite{HaboeckLubarovNabaglo2023,HaboeckLevitPapini2024}.  The S-two
whitepaper gives the closest published concrete circle-code protocol and
Fiat--Shamir accounting \cite{CarmonEtAl2026Stwo}.

The evaluated Aspis verifier has a distinct four-way fold, two initial
commitments, three later Merkle layers, bounded query sampler, algebraic
relation, and six-step work schedule.  The Lean development proves its
encoder identities, causal candidate chain, query distribution, and relation
composition for those parameters.  It imports the stated circle-decoding and
Fiat--Shamir results at explicit interfaces.  Work on proximity gaps and
mutual correlated agreement supplies the mathematical setting for the
candidate analysis
\cite{BenSassonCarmonIshaiKoppartySaraf2023,
BordageChiesaGuanManzur2025,Haboeck2025MCA,CritesStewart2025}.

\subsection{Machine-checked cryptography and implementations}

EasyCrypt established a practical framework for machine-checked game-based
cryptographic proofs \cite{BartheEtAl2012EasyCrypt}.  Machine-checked
MPC-in-the-head work proves security for a general zero-knowledge construction
and connects it to executable components
\cite{AlmeidaEtAl2021MitH}.  Jasmin, HACL*, and Fiat-Crypto demonstrate
strong links between proof and efficient cryptographic code through verified
compilation, extraction, or generation
\cite{AlmeidaEtAl2017Jasmin,ZinzindohoueEtAl2017HACL,
ErbsenEtAl2019FiatCrypto}.

For proof systems, ArkLib develops a modular Lean theory of interactive oracle
reductions, composition, and knowledge soundness \cite{ArkLib2026}.  Work on
verifying deployed zero-knowledge verifiers stresses the need to connect an
abstract security proof to the code that parses and accepts proofs
\cite{FirsovLivshits2024}.  Aspis contributes an application-specific point in
this design space: functional translation of a successful Rust verifier path,
same-execution composition through every acceptance check, private-spend and
state semantics, and reproducible binary and transaction evidence.

\subsection{Private payments and Solana}

Zerocash established the note-commitment and nullifier pattern used by modern
shielded payments \cite{BenSassonEtAl2014Zerocash}.  On Solana, Protocol~01
publishes a transparent STARK-based shielded-payment stack and documented
devnet verifier \cite{Protocol01Repository2026}.  The solana-pqzk-fullchain
project directly verifies a Winterfell STARK on devnet and reports
reproducible costs for an affine-counter statement
\cite{Yano2026SolanaPQZK}.  Privacy Cash records a mainnet shielded-state
deployment using Groth16, and Light Protocol publishes setup material for its
Groth16 proving stack
\cite{PrivacyCashSetup2026,PrivacyCashMainnet2026,
LightProtocolSetup2026}.

The contribution claimed in this paper is the combination of a transparent
private-spend verifier, same-transaction nullifier and pool update, an
end-to-end theorem for the successful proof-checking path, reproducible
program bytes, and archived mainnet evidence.  A public-evidence search
completed on 24 August 2026 found no earlier public artifact with that complete
combination.  The comparison is dated and limited to publicly indexed papers,
repositories, deployments, and patents.
