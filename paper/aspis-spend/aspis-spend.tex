\begin{abstract}
Aspis develops an evidence chain from private-spend mathematics to a
finalized Solana execution.  The maintained Lean~4 development kernel-checks
the relation core, finite security arithmetic, circle-group facts, masking
    lemmas, and theorem composition.  For the selected V5 release scope, Charon
    extracts selected production Rust and Aeneas translates it into Lean; bridge
    proofs connect the generated definitions to maintained verifier models,
    public output, Tag-67 decoding, and the six ordered work checks.  A clean
    build from the identified source reproduces
the 1,258,496-byte Solana bytecode format (SBF) binary byte-for-byte.  That
binary was deployed on mainnet-beta, where a finalized Tag-67 transaction
verified a 75,358-byte proof, created the canonical nullifier marker, and
advanced the pool sequence atomically.  Exact signed-wire simulation and
landed metadata both report 1,334,452 compute units.

The paper's quantitative security case study remains the distinct frozen
$q=\ProfileQueryCount$, $g=\ProfileBatchWork$ release.  Its custom
circle-domain, WHIR-style multilinear protocol has rate $1/512$.  The frozen
event ledger and 32-boundary Fiat--Shamir reduction give a conservative
\ProfileSoundnessBits-bit floor for work-normalized false acceptance per
random-oracle query under the stated finite-parameter and
boundary-state-restoration premises.  Under the stated affine-image premise,
an explicit witness-free simulator gives \ProfileSimulationBits{} bits for
real view versus simulation and \ProfilePairwiseBits{} bits for pairwise
witness-indistinguishability in the declared programmable-SHA-256
Proof-or-Abort view.  That q18/g37 release used a
\ProfileProofBytes-byte proof, a \ProfileSbfBytes-byte SBF binary, and
\ProfileMainnetComputeUnits{} compute units on mainnet.  These bounds are not
silently transferred to V5; the later V5 execution is separate evidence for
the source-linked implementation and deployment path.

The formal Rust correspondence is limited to selected verifier paths:
Component~A at the release schedule, the Component-B/C evaluator and public
output paths, and the Tag-67 work-byte and six-step verifier.  Its sole
remaining Tag-67 implementation-to-model premise equates one extracted
transcript-hash function application with the maintained hash call.  The
result additionally
assumes the Charon/Aeneas and Rust-to-SBF toolchains, the Solana loader and
runtime semantics, SHA-256 and the cited cryptographic primitives; it has not
received an external security audit.  Proof transport and account setup occur
before the atomic spend.  The demonstrated relation is a same-path,
one-input/one-output leaf replacement, not a complete wallet, deposit system,
or growing anonymity set.
\end{abstract}
